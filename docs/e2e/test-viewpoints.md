# inusta-next E2E テスト観点

## テスト対象機能
- **認証**：新規登録、ログイン、ログアウト
- **プロフィール**：表示、編集
- **投稿**：新規作成、編集、削除
- **コメント**：新規作成、編集、削除

---

## 認証機能のテスト観点

### 1. 新規会員登録

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| 基本的な登録フロー | 新規ユーザー情報を入力して登録 | <ul><li>ユーザー名、メールアドレス、パスワード、パスワード確認が入力可能</li><li>登録ボタンをクリックするとアカウントが作成される</li><li>登録後、ホーム画面（/posts）へ遷移する</li></ul> | 高 |
| ユーザー名の入力検証 | ユーザー名を空にして登録を試行 | <ul><li>エラーメッセージが表示される</li><li>アカウントが作成されない</li></ul> | 高 |
| メールアドレスの入力検証 | 不正なメール形式で登録を試行 | <ul><li>エラーメッセージが表示される</li><li>アカウントが作成されない</li></ul> | 高 |
| メールアドレスの重複チェック | 既に使用されているメールアドレスで登録を試行 | <ul><li>「メールアドレスは既に使用されています」というエラーメッセージが表示される</li><li>アカウントが作成されない</li></ul> | 高 |
| パスワードの長さ検証 | 8文字未満のパスワードで登録を試行 | <ul><li>エラーメッセージが表示される（最小8文字が必要）</li><li>アカウントが作成されない</li></ul> | 高 |
| パスワード確認の一致チェック | パスワードとパスワード確認が異なる状態で登録を試行 | <ul><li>エラーメッセージが表示される（パスワードが一致していません）</li><li>アカウントが作成されない</li></ul> | 高 |
| 正常な登録後のセッション確立 | 正しい情報で登録を完了 | <ul><li>ユーザーが自動的にログイン状態になる</li><li>ダッシュボードへのアクセスが可能</li><li>プロフィールページで作成されたユーザー情報が表示される</li></ul> | 高 |

### 2. ログイン

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| 基本的なログインフロー | 正しいメールアドレスとパスワードでログイン | <ul><li>ホーム画面へ遷移する</li><li>ログイン状態が確立される</li></ul> | 高 |
| メールアドレスが未登録 | 登録されていないメールアドレスでログインを試行 | <ul><li>エラーメッセージが表示される</li><li>ログインが失敗し、ログインページに留まる</li></ul> | 高 |
| パスワードが間違っている | 正しいメールアドレスで誤ったパスワードでログインを試行 | <ul><li>エラーメッセージが表示される</li><li>ログインが失敗し、ログインページに留まる</li></ul> | 高 |
| 入力フィールドの必須チェック | メールアドレスまたはパスワードを空欄のまま送信を試行 | <ul><li>ブラウザの標準バリデーション、またはエラーメッセージが表示される</li><li>ログインが進行しない</li></ul> | 高 |
| ログイン後のリダイレクト | ログイン成功後の遷移先 | <ul><li>ダッシュボードまたはホーム画面へ遷移する</li><li>保護されたページへのアクセスが可能</li></ul> | 中 |

### 3. ログアウト

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| ログアウト機能の動作 | ユーザープロフィールの設定から「ログアウト」をクリック | <ul><li>セッションが終了される</li><li>ログインページへ遷移する</li><li>ログアウト後、保護されたページへのアクセスが不可になる</li></ul> | 高 |
| ログアウト後のブラウザバック | ログアウト後、ブラウザバックボタンで前ページへアクセス | <ul><li>ダッシュボードなど保護されたページにはアクセスできない</li><li>ログインページにリダイレクトされる</li></ul> | 中 |

## プロフィール機能のテスト観点

### 4. プロフィール表示

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| ユーザープロフィールの表示 | プロフィール編集ページへアクセス | <ul><li>ユーザー名、メールアドレス、自己紹介、プロフィール画像が表示される</li><li>各項目が正しい値で表示されている</li></ul> | 高 |
| プロフィール画像の表示 | プロフィール画像が設定されている状態で表示 | <ul><li>プロフィール画像がプレビューに表示される</li><li>画像が正しくレンダリングされている</li></ul> | 中 |
| プロフィール画像がない場合 | プロフィール画像が未設定の状態で表示 | <ul><li>デフォルト画像またはプレースホルダーが表示される</li><li>ファイル選択が可能な状態</li></ul> | 中 |

### 5. プロフィール編集

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| ユーザー名の編集 | ユーザー名を新しい値に変更して保存 | <ul><li>ユーザー名が更新される</li><li>ダッシュボードなど全画面でユーザー名が反映される</li><li>プロフィール編集ページを再表示しても更新内容が保持されている</li></ul> | 高 |
| メールアドレスの編集 | メールアドレスを新しい値に変更して保存 | <ul><li>メールアドレスが更新される</li><li>新しいメールアドレスでログインが可能</li><li>古いメールアドレスではログインできない</li></ul> | 高 |
| メールアドレスの重複チェック | 既に他のユーザーが使用しているメールアドレスに変更を試行 | <ul><li>エラーメッセージが表示される</li><li>メールアドレスが更新されない</li></ul> | 高 |
| 自己紹介の編集 | 自己紹介テキストを編集して保存 | <ul><li>自己紹介が更新される</li><li>ユーザー一覧やプロフィールページで更新内容が表示される</li></ul> | 高 |
| 自己紹介の文字数制限 | 500文字を超えるテキストを入力 | <ul><li>入力が500文字で制限される</li><li>文字数カウントが「500 / 500」と表示される</li><li>超過分は入力されない</li></ul> | 中 |
| 自己紹介が空の場合 | 自己紹介を空のまま保存 | <ul><li>更新が成功する</li><li>プロフィール編集ページの自己紹介は空で表示される</li></ul> | 中 |
| プロフィール画像のアップロード | 対応する画像形式（JPEG, PNG, WebP, GIF）をアップロード | <ul><li>ファイル選択後、プレビューに画像が表示される</li><li>保存ボタンをクリックして画像が更新される</li><li>ダッシュボード等他の画面でも新しい画像が反映される</li></ul> | 高 |
| プロフィール画像の形式チェック | 対応していない形式（例：BMP、TIFF）をアップロード | <ul><li>エラーメッセージが表示される（「対応する形式：JPEG, PNG, WebP, GIF」）</li><li>ファイルが選択されない</li></ul> | 中 |
| プロフィール画像のファイルサイズチェック | 5MBを超える画像をアップロード | <ul><li>エラーメッセージが表示される（「ファイルサイズは5MB以下にしてください」）</li><li>ファイルが選択されない</li></ul> | 中 |
| プロフィール画像の更新反映 | プロフィール画像を変更して保存 | <ul><li>ユーザーのプロフィールページで新しい画像が表示される</li><li>他のユーザーがそのユーザーのプロフィールを表示した時、新しい画像が見える</li><li>ユーザー一覧やコメント欄など、ユーザー画像が表示される箇所で新しい画像が反映される</li></ul> | 高 |
| ユーザー名の必須チェック | ユーザー名を空のまま保存を試行 | <ul><li>エラーメッセージが表示される（「名前は必須です」）</li><li>プロフィール情報が更新されない</li></ul> | 高 |
| 保存ボタンの状態 | 編集中の保存ボタン | <ul><li>ローディング中は「保存中...」と表示される</li><li>ローディング中は入力フィールドが無効化される</li><li>保存完了後は「保存」に戻る</li></ul> | 中 |
| エラーハンドリング | プロフィール更新に失敗した場合 | <ul><li>エラーメッセージが表示される</li><li>ユーザーが修正して再度保存を試みることが可能</li></ul> | 中 |

## 投稿機能のテスト観点

### 6. 投稿新規作成

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| 投稿作成の反映 | ユーザーAが投稿を新規作成し、ユーザーBでログイン | <ul><li>ホーム画面に新規投稿が表示される</li><li>投稿一覧の上部に表示される</li><li>投稿の作成者名、画像、キャプション、コメント件数(初期値:0)が正しく表示される</li></ul> | 高 |
| ユーザー一覧の件数反映 | ユーザーAが投稿を新規作成し、ユーザーBでログイン | <ul><li>ユーザー一覧画面でユーザーAの「投稿 X 件」が増加している</li><li>投稿数が多い順ソート時に順位が変更される</li></ul> | 高 |
| ユーザープロフィールの投稿反映 | ユーザーAが投稿を新規作成し、ユーザーBでログイン | <ul><li>ユーザーAのプロフィール画面に新規投稿が表示される</li><li>プロフィール画面の「投稿X件」が増加している</li><li>投稿グリッドの上部に新規投稿が表示される</li></ul> | 高 |
| 投稿詳細ページの表示 | 新規作成した投稿の詳細ページを別ユーザーで表示 | <ul><li>投稿の全情報が正しく表示される（画像、キャプション、ユーザー情報）</li><li>作成日時が正しく表示される</li><li>コメント件数が0件と表示される</li></ul> | 中 |

### 7. 投稿編集

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| 投稿内容の編集反映 | ユーザーAが投稿を編集し、ユーザーBでログイン | <ul><li>ホーム画面で編集された投稿内容が表示される</li><li>キャプションが更新されている</li><li>画像が更新されている場合、新しい画像が表示される</li></ul> | 高 |
| ユーザープロフィールでの編集反映 | 投稿を編集後、他のユーザーで当該ユーザーのプロフィールを表示 | <ul><li>プロフィール画面の投稿グリッドに編集済み投稿が表示される</li><li>編集内容が反映されている</li></ul> | 高 |
| 投稿詳細ページでの編集反映 | 投稿を編集後、詳細ページを再表示（別ユーザーで） | <ul><li>投稿内容が編集済みの状態で表示される</li><li>キャプション、画像が最新の状態である</li></ul> | 中 |
| 編集ボタンの表示制御 | ユーザーAが作成した投稿を別ユーザーBで表示 | <ul><li>投稿詳細ページで編集ボタンが表示されない（または無効化されている）</li></ul> | 中 |

### 8. 投稿削除

| 観点 | シナリオ | 検証ポイント | 優先度 |
|------|--------|-----------|-------|
| 投稿削除のホーム画面での反映 | ユーザーAが投稿を削除し、ユーザーBでログイン | <ul><li>ホーム画面から削除された投稿が表示されない</li><li>ホーム画面の投稿一覧から消えている</li></ul> | 高 |
| 投稿削除のユーザー一覧での件数反映 | 投稿を削除後、ユーザー一覧を表示（別ユーザー） | <ul><li>当該ユーザーの「投稿 X 件」が減少している</li><li>削除前の件数から1件減っている</li><li>投稿数が多い順ソート時に順位が変更される可能性がある</li></ul> | 高 |
| 投稿削除のプロフィール画面での反映 | 投稿を削除後、当該ユーザーのプロフィールを表示（別ユーザー） | <ul><li>プロフィール画面の投稿グリッドから削除された投稿が表示されない</li><li>「投稿X件」の数が減少している</li></ul> | 高 |
| 削除投稿への直接アクセス | 削除された投稿の詳細ページURLに直接アクセス | <ul><li>404エラーまたはエラーページが表示される</li><li>投稿が存在しないことが表示される</li></ul> | 中 |

## 共通条件

### テスト実行時の前提条件
- 2つ以上の異なるユーザーアカウントでテストを実施
- 各ステップ後、ブラウザのキャッシュをクリアするか、別ブラウザ/シークレットモードで確認
- 同時に複数ユーザーでアクセスする場合、リアルタイム反映を確認

### テスト実行対象画面一覧
| 画面 | URL | 表示情報 |
|-----|-----|--------|
| ログインページ | `/login` | メールアドレス入力フィールド、パスワード入力フィールド、ログインボタン、新規会員登録リンク |
| 新規会員登録ページ | `/register` | ユーザー名入力フィールド、メールアドレス入力フィールド、パスワード入力フィールド、パスワード確認フィールド、登録ボタン |
| 登録完了ページ | `/register/complete` | 登録完了メッセージ、ホームへのリンク |
| プロフィール編集ページ | `/profile` | ユーザー名、メールアドレス、自己紹介、プロフィール画像の編集フォーム |
| ダッシュボード | `/dashboard` | ユーザー情報、投稿一覧、プロフィール編集・ログアウト操作 |
| ホーム画面 | `/posts` | 全投稿のグリッド表示（画像、ユーザー名、キャプション、コメント件数） |
| ユーザー一覧 | `/users` | 全ユーザーのリスト（ユーザー名、投稿件数） |
| ユーザープロフィール | `/users/{id}` | ユーザー情報、投稿件数、投稿グリッド |
| 投稿作成ページ | `/posts/create` | 画像アップロード、キャプション入力フォーム |
| 投稿詳細ページ | `/posts/{id}` | 投稿情報、ユーザー情報、キャプション、コメント一覧、コメント追加フォーム |
| 投稿編集ページ | `/posts/{id}/edit` | 投稿画像、キャプション編集フォーム |

## 優先度の定義
- **高**：ユーザーがアプリを使用する際の主要な機能で、反映されないと基本的な利用体験に影響
- **中**：重要な機能だが、優先度高に比べるとユーザーへの影響は限定的
